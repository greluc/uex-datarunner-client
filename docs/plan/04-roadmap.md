# Roadmap

> **Doc type:** Living plan — active. Last reviewed: 2026-10-09.

Order by risk and benefit: first the API uncertainties are clarified. Then follows **manual capture plus submission**; that is already a usable product without OCR. After that comes the OCR. Effort is deliberately not estimated in days, because the team's availability and experience are unknown.

## Risks

| Risk | Impact | Countermeasure / check |
|---|---|---|
| UEX requires an app token that an open-source client cannot distribute securely (A2) | **Project blocker** for submission | M0: clarify early with UEX; option "user enters their own app token". Verified 2026-10-09: the token is required. Decided 2026-10-09 (O-85): every user creates and enters their own token |
| UEX terms of use exclude third-party clients or automated capture | Project blocker | M0: read the terms and obtain approval if necessary |
| PP-OCR is too inaccurate as the primary reader for terminals | Lots of manual correction; core benefit drops | M2 measures early; countermeasures: fine-tuning the recognition model, VLM second reader (M5) |
| Game patch changes the terminal layout | Recognition breaks | Data-driven layout profiles, crop dumps, corpus regression test; manual cropping as fallback |
| Toolchain does not support JDK 27 | Build blocked | M0 check; fallback JDK 25 LTS |
| Linux specifics (Wine paths, game detection, Secret Service, XWayland) deviate from the assumptions | Linux functions restricted | Manual configuration as fallback everywhere; tests on real systems in M4/M5 |
| Compromised dependency, CI action or compromised build artifact | Malicious code at users, theft of the secret key | Measures S-1…S-37 in [10](10-supply-chain-security.md); residual risk "malicious, correctly signed new version" remains medium |
| UEX API changes (fields, error codes) | Submission fails | Defensive parsing, contract tests with recorded responses, understandable error messages |
| No access to an HDR monitor, an ultrawide monitor or some capture tools | Classes stay `synthetic only`/`missing`; HDR and ultrawide independence cannot be shown | Publish the capture protocol (07 §4) so that DataRunners can contribute redacted full frames; synthetic variants as interim coverage; unverified classes named in the release notes |
| Licence non-compliance in a release: missing notices or source archives, a GPL-incompatible runtime dependency, the default `.deb` copyright file claiming every file for the GPL | Licence violation; loss of the right to distribute the bundled OpenJDK and OpenJFX (GPL-2.0 §4) | Licence gate and `reuse lint` from M0 (10 S-34, S-35); notices directory with a build test (R-DOC-3); source archives per release (R-DOC-4); release checklist steps 6–7 |
| Proprietary Microsoft C/C++ runtime in the Windows packages (DLLs from the JDK and JavaFX; linked statically into the jpackage launcher and `msica.dll`) | Unclear GPL compatibility of the Windows distribution | For now the GPL-3.0 System Library definition; a legal review before the first release; a narrow GPL-3.0 §7 permission, if wanted, before the first external contribution (O-12) |
| ONNX Runtime telemetry cannot be switched off reliably | The privacy gate (02 §9) is broken | M0 network spike; R-NF-12 mitigation; fallback: an ORT build with `--no_telemetry` (O-13); telemetry is never accepted silently |
| The Fan Kit terms change, or the unit is rendered in a non-compliant way | Loss of the permission to use the Fan Kit logo | Byte-exact pinning tests (R-UI-19); checked kit version recorded in `NOTICE` and re-checked when a newer kit is published; every change of the unit needs the project owner's approval |
| WiX v6 or later needs the Open Source Maintenance Fee EULA; the MSI embeds MS-RL files | The MSI build is blocked without the owner's acceptance; licence questions about the MSI container | WiX major chosen in M1 (O-11), the EULA accepted explicitly by the project owner and recorded in the release process; plain app-image ZIP next to the MSI; MS-RL text and WiX source with every MSI |
| Cloud Imperium's terms do not allow game screenshots in a public repository | Corpus images must be removed | The project owner checks the RSI Terms of Service and the Fankit and Fandom FAQ (O-28); images marked `LicenseRef-Game-Screenshots`; the transcriptions stay under the project licence |
