# Roadmap

> **Doc type:** Living plan — active. Last reviewed: 2026-10-14.

Amended 2026-10-12 ([ADR-0005](../adr/0005-rust-and-egui.md)): the milestones now build a Rust and egui application. "Module" reads as "Cargo workspace crate" (the context cut of ADR-0002 is unchanged), M0 is rewritten for the Rust toolchain, the supply chain and the new spikes, and the Java-specific items (JDK 27 toolchain check, jlink and ONNX Runtime merge, JavaFX screen-reader spike, JVM heap limits) are gone. The acceptance criteria keep their meaning.

Order by risk and benefit: first the API uncertainties are clarified. Then follows **manual capture plus submission**; that is already a usable product without OCR. After that comes the OCR. Effort is deliberately not estimated in days, because the team's availability and experience are unknown.

## Risks

| Risk | Impact | Countermeasure / check |
|---|---|---|
| UEX requires an app token that an open-source client cannot distribute securely (A2) | **Project blocker** for submission | M0: clarify early with UEX; option "user enters their own app token". Verified 2026-10-09: the token is required. Decided 2026-10-09 (O-85): every user creates and enters their own token |
| UEX terms of use exclude third-party clients or automated capture | Project blocker | M0: read the terms and obtain approval if necessary |
| PP-OCR is too inaccurate as the primary reader for terminals | Lots of manual correction; core benefit drops | M2 measures early; countermeasures: fine-tuning the recognition model, VLM second reader (M5) |
| Game patch changes the terminal layout | Recognition breaks | Data-driven layout profiles, crop dumps, corpus regression test; manual cropping as fallback |
| `ort` exists only as a release candidate (`=2.0.0-rc.13`), an explicit exception to "stable releases only" (ADR-0005 D2) | API or behaviour changes, or defects, in the ONNX binding; no stable release to rely on | Exact pin; the binding is confined to `adapter-ocr` behind a port; the OCR digest test (R-QA-4) catches changed output; the M0 link-mode and telemetry spikes; moving to the first stable release is its own pull request; a pure-Rust ONNX path (`tract`, `rten`) stays an optional fallback (ADR-0005 "Alternatives considered") |
| Native code in dependencies by registered exception (ADR-0005 D1, D2): ONNX Runtime (C++) through `ort`, SQLite (C) through `rusqlite`, the C and assembler parts of the `rustls` provider (`aws-lc-rs`, ADR-0006) | Memory-unsafe code and an extra supply-chain and licence surface outside Rust's guarantees; the licence of the native parts | Each exception is registered in 09 §3b with crate, native part, reason, licence and revisit date; the TLS provider's licence and audit state were checked on 2026-10-14 (O-110, ADR-0006); SQLite is revisited against Turso Database in a year (O-109); `cargo-vet`, `cargo-audit`/OSV and vendor hashes cover the crates; every other crate has `#![forbid(unsafe_code)]` |
| The review table, in-cell editing, the searchable combo box and keyboard navigation are our own work on egui (no ready-made editable table) | The review UI, the centre of the product, costs more than planned or feels worse than a mature toolkit's | The M0 review-table prototype with 200 rows and the Tallyline cell states decides before M1; a failure reopens the toolkit choice (ADR-0005 D3) |
| Linux specifics (Wine paths, game detection, Secret Service, X11 and native Wayland) deviate from the assumptions | Linux functions restricted | Manual configuration as fallback everywhere; tests on real systems in M4/M5 |
| Compromised dependency, CI action or compromised build artifact | Malicious code at users, theft of the secret key | Measures S-1…S-37 in [10](10-supply-chain-security.md); residual risk "malicious, correctly signed new version" remains medium |
| UEX API changes (fields, error codes) | Submission fails | Defensive parsing, contract tests with recorded responses, understandable error messages |
| No access to an HDR monitor, an ultrawide monitor or some capture tools | Classes stay `synthetic only`/`missing`; HDR and ultrawide independence cannot be shown | Publish the capture protocol (07 §4) so that DataRunners can contribute redacted full frames; synthetic variants as interim coverage; unverified classes named in the release notes |

| Proprietary Microsoft C/C++ runtime in the Windows packages (the DLLs that `onnxruntime.dll` imports; our own binary can link the C runtime statically, ADR-0005 Consequences) | Unclear GPL compatibility of the Windows distribution | For now the GPL-3.0 System Library definition; a legal review before the first release; a narrow GPL-3.0 §7 permission, if wanted, before the first external contribution (O-12) |
